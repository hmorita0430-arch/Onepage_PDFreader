# 設計メモ(実装での判断と、要件定義書との関係)

要件定義書(`docs/requirements.md`)に明記されていない点を、実装時にどう決めたかの記録。
要件と食い違う可能性がある項目は「要確認」とした。

## 第2段階

| 項目 | 実装での判断 | 区分 |
|---|---|---|
| 余白の共通枠の向き | 共通枠(`cropFrame`)は **右ページ基準**で保存し、左ページには **左右反転**で適用する。綴じ目側と小口側の余白は、見開きで対称なため | 要確認 |
| ページ単位の余白のキー | `pageOverrides` のキーは、見開き単位の項目(split 等)は `"<pdfPage>"`、**ページ単位の余白だけ** `"<pdfPage>:<L\|R\|W>"` とした。左右のページで別々に持つため。4章の形式への追加であり、既存データには影響しない | 要確認(4章への追記) |
| 余白の設定画面 | スライダー4本(上・下・左・右、0〜40%)と、削る範囲の暗表示。枠のドラッグ操作は未対応 | 判断 |
| 2ページ表示(D-6) | 「撮影した見開き1枚の左右をそのまま並べる」ため、左右それぞれのトリミング範囲を含む、元画像上の連続した1つの矩形を描画する(綴じ目付近は撮影のまま)。ページ送りは見開き単位。横長(幅>高さ)のときだけ有効 | 判断 |
| 表紙(片側だけの1枚目)の2ページ表示 | その1ページだけを表示する | 判断 |
| ズーム | 倍率 1〜6。ダブルタップ/ダブルクリックは「フィット⇔2.5倍」の切り替え(画面中央付近のみ。端のダブルタップは2回のページ送りになるため) | 判断 |
| ズーム中の操作 | ドラッグは表示位置の移動のみ。ページ送りは左右端のタップとキー(O-1, O-3) | 要件どおり |
| ズーム維持(D-9) | 倍率と、ビューポート中央に来る「トリミング後ページ内の相対位置(0〜1)」を引き継ぐ。ページの形が違っても同じ相対位置を表示する。ただし端の外は、到達できる最も近い位置に寄る | 要件(提案)どおり |
| 描画解像度 | フィット表示の2倍(上限1,000万画素)で描き、拡大はCSS変換で行う。最大倍率では粗く見える場合がある | 判断 |
| キー操作 | `+` `-` `0`(ズーム)、`Home`/`End`、左右矢印は **開き方向に連動**(右開きは ← が次)。上下・PageUp/PageDown も前後 | 要確認(8章「矢印キーで前後」の解釈) |
| 最後に読んだ位置(N-1) | ページを開くたび、400ms 後に保存。表示中の論理ページ(物理位置)を保存する。2ページ表示では見開きの先頭ページ | 要件どおり |
| 端末内保存(G-4) | IndexedDB に本ごとのPDFを保存。ドライブ上の md5 が同じ版なら、取得し直さず保存済みを使う。保存時に `navigator.storage.persist()` を要求する | 要件(提案)どおり |
| 保存済みの本の一覧からの「開く」 | 要件G-1は「本棚機能は持たない」だが、G-4の「保存済みの本の一覧・削除」に開く操作を付けた(オフラインではピッカーが使えないため) | 要確認 |
| 取得の再開(5章 提案) | 4MiBごとに Range 取得し、取得済みの断片を IndexedDB に保存。接続切れ後は続きから再開する。ファイルが変わっていれば(サイズか md5 が違う)最初から | 要件(提案)どおり |
| オフライン起動 | サービスワーカーでアプリ本体(JS/CSS/pdf.js ワーカー)をキャッシュする。書籍データは含めない。外部(Google)通信には介入しない | 判断 |
| 開発用の「端末のPDFを開く」 | 開発サーバーでのみ表示。本番ビルドには含まれない | 判断 |

## 第3段階

| 項目 | 実装での判断 | 区分 |
|---|---|---|
| 同期データの保存 | 本1冊につき1ファイル `book-<ドライブのファイルID>.json` をアプリ専用領域(appDataFolder)に保存。内容は4章の形式(`BookSyncDocument`)そのまま | 要件どおり |
| 統合規則 | 4章どおり。注釈・名前つきページは1件ごとにID+更新日時、位置は新しい方、設定は項目ごとに新しい方。同時刻は内容の比較で決め、どの順序で統合しても同じ結果になる(可換・冪等・結合的。単体テストで確認) | 要件どおり |
| 他端末と同時に書いたとき | 書き込みの直前にファイルの版(version)を確認し、変わっていれば取り込み直して統合し直す(最大3回)。他端末の分を上書きで消さない | 判断 |
| 同期のタイミング | 本を開く前(接続中なら5秒まで待つ)、変更の5秒後、本を閉じる時、画面を隠した時・**戻った時**、フォーカス時、ネットワーク復帰時、**開いている間は30秒ごと**、再接続した時、「今すぐ同期」。サーバーを持たないため、アプリを閉じている間の自動同期はできない | 判断(下の「同期体験の改善」で更新) |
| 未同期の件数(G-3) | 前回の同期で確定した内容との差。名前つきページ・注釈は1件ずつ、変えた設定は1項目ずつ。画面左下に常に表示する。**最後に読んだ位置は件数に含めない**(ページを送るたびに変わるため)。位置だけが未送信で未接続のときは、その旨を表示する | 要件(提案)どおり |
| 削除 | 消さずに「削除済み」の印(墓標)を残す。印は消さない(増え続けるが、1件は数百バイトで、個人利用では問題にならない規模) | 要件どおり |
| 新しい形式のデータ | 同期データの `schemaVersion` が、このアプリより新しければ読まず・書かない(古いアプリが新しいデータを壊さないため) | 判断 |
| 位置の反映 | 本を開く前の同期で、他端末の最後に読んだ位置から開く。開いた後の同期では、表示中のページは動かさない。**位置の更新日時は、利用者がページを移動したときだけ更新する**(画面サイズの変化・画面を隠す・閉じるでは更新しない。更新すると、動いていない端末の古い位置が、他の端末の新しい位置に勝ってしまう) | 判断(不具合の修正を反映) |
| ページジャンプ(N-2) | 通し番号と、印刷ページ番号(対応を設定済みのときのみ)の両方でジャンプできる。8章の未決事項「印刷番号でもジャンプするか」は、**できる**側に仮決め | 要確認 |
| しおり・目次(N-4) | 1つの仕組みで種類(しおり/目次)を切り替え。ページ順に表示。目次は名前が必須、しおりは名前を省略するとページ表記が入る | 要件どおり |
| サムネイル(N-3) | 見えている付近だけを順に読み込む(1枚ずつ)。分割位置・余白トリミングを反映した1ページ表示で作る。本を閉じるとき破棄する | 判断 |
| 権限の追加 | 第3段階から `drive.appdata` を要求する。第2段階までに接続済みの場合、次の接続で追加の許可画面が1回出る | 要件どおり |
| 同期しないもの | 開発用の「端末のPDFを開く」で開いた本(ドライブに紐づかないため) | 判断 |

## 同期体験の改善(利用者のフィードバックを受けた変更)

「両方を開いているときにどちらがどちらに反映されるか分かりにくい」「再接続の手間」「反映されない・遅い」への対応。

| 課題(原因) | 対応 | 区分 |
|---|---|---|
| 他の端末の変更を、開いたままの端末が取りに行かなかった(自分の変更時にしか同期しなかった) | 開いている間は30秒ごと、画面に戻ったとき、フォーカス時、ネットワーク復帰時に確認する。ドライブ上のファイルの版が変わっていなければ、本体は読み込まない(通信量の削減) | 判断 |
| 「同期済み」が「自分の変更を送った」だけの意味で、最新かどうか分からなかった | 「最新(10:42に確認)」と、ドライブ上の状態を確認できた時刻で表示。取り込み・送信は「↓他の端末から しおり・目次1件 を取り込み」「↑1件を送信」と、方向と内容を8秒間表示する | 判断 |
| 他の端末の読書位置が分からない(開く前の同期でしか反映されない) | 他の端末の位置の方が新しいとき、「他の端末の読書位置: p.45 [移動]」と尋ねる。**表示中のページは勝手に動かさない** | 判断 |
| アクセストークンがメモリ上だけで、アプリを開き直すたびに接続が消えた | **有効期限(約1時間)の間だけ、トークンを端末内(localStorage)に保存**し、開き直しても接続を引き継ぐ。期限切れ・401・「この端末の接続情報を消す」で即座に消す。権限はアプリ専用領域と選んだPDFに限られる | 利用者が採用を承認(2026-11-13)。**この端末を他人が使える状態だと、期限内は悪用される余地がある** |
| 未接続の状態では、再接続ボタンが出なかった(切れた後にしか出ていなかった) | 未接続でも「ドライブに接続」、切れたときは「再接続」を常に表示 | 不具合の修正 |
| 再接続に、メニューを開いてボタンを押す手間がかかった | 接続が切れたあと、**次の画面操作で自動的に再接続を試みる**(設定でオフにできる)。失敗・キャンセルしても繰り返さない。Googleのスクリプトは起動時に先読みし、ポップアップを操作の直後に開けるようにする | 判断。**実際のGoogleでの動作(ポップアップの出方)は未確認** |
| 1時間ごとの再接続そのものは残る | サーバーを持たない構成では、Googleが自動更新を許していないため、仕様として残る。再接続の手間を減らすのみ | 制約 |

## 位置の同期の不具合修正(2026-11-13)

| 症状 | 原因 | 対応 |
|---|---|---|
| PC側は「スマホの位置へ移動しますか」と出るが、スマホ側はPCの移動を受け取らない | 最後に読んだ位置を、ページを移動したときだけでなく、画面サイズの変化・画面を隠す・閉じるたびに「いま」の時刻で保存し直していた。「新しい方が勝つ」ため、操作していないスマホの古い位置が、PCの新しい位置を上書きした | 利用者がページを移動したときだけ保存する。再現手順を操作テストに追加し、修正前に失敗・修正後に成功することを確認 |
| スマホが古い版のまま動いている可能性(確認できていない) | 配信後の初回は旧版が表示される(サービスワーカー) | 設定と開始画面に「バージョン(コミットID)」を表示。新しい版が来たら「新しい版があります [更新]」を表示。画面に戻ったときに新しい版を確認する |

**残る不確かさ(事実として未確認)**: 端末どうしの時計のずれ。位置・設定は端末の時計で「新しい方」を決めるため、時計が大きくずれた端末では、古い操作が勝つ可能性がある(サーバーを持たないため、補正の手段が限られる)。

## 第4段階

| 項目 | 実装での判断 | 区分 |
|---|---|---|
| 出力先 | マイドライブ/**読書ノート**/本の名前/ に `読書ノート.md` と `images/page-NNN.jpg`。フォルダは初回に自動作成。何度書き出しても、同名のファイルは更新する(重複しない) | 利用者が決定(フォルダ名) |
| `drive.file` の制約 | この権限は「アプリが作ったファイル・フォルダ」だけを扱える。**利用者が手で作った同名の「読書ノート」フォルダは見えず**、アプリ用に別の同名フォルダが作られる | 制約(事実) |
| Markdown | 注釈のあるページだけを、読む順に。ページ番号は「p.45(通し番号52)」の併記。メモは作成順に「メモ1」「メモ2」(画像の丸の番号と一致)。蛍光ペンは色の名前と、OCRの文字(あれば) | 要件+利用者の決定 |
| OCRの文字 | 蛍光ペンの範囲(自由線は線を囲む矩形)に中心が入る文字を、PDF内の順に連結する。文字データが無ければ「(文字データなし)」。縦書きでも内容順なので、並びがずれる可能性がある。OCRの誤認識はそのまま出る(注記を付ける) | 利用者が決定 |
| 画像 | 注釈のあるページごとに、長辺1800pxのJPEG。**分割・トリミング後の1ページ**に注釈を重ねる(トリミングで切った範囲の注釈は写らない)。蛍光ペンは乗算で文字を隠さない。メモは番号つきの丸 | 判断 |
| 書き出しの前提 | ドライブに接続中であること(切れていれば、再接続を案内)。端末へのダウンロードは未対応 | 判断(要件A-5は「ドライブに直接保存」) |
| ツール | 四角・なぞる(自由線)・メモ・消す。色は黄・緑・ピンク・青(最後に選んだ色とツールを記憶)。自由線の太さは元画像の幅の1.2%で固定 | 要件(仮置き)どおり |
| O-4 | ツール使用中は、タップ・スワイプでページ送りしない。ページ送りはツールバーの ◀ ▶ とキー。拡大は2本指・ホイール、ズーム中の移動は2本指(マウスは Shift+ドラッグ) | 要件どおり+判断 |
| 座標 | 元画像基準の正規化座標。分割位置・トリミング・ズームを変えても同じ画像上の場所に付く(操作テストで確認)。「どちら側か」は、作成時の分割位置で決める(矩形・自由線は中心) | 要件どおり |
| 消す | 蛍光ペンは、画面上約10pxの余裕でタップ判定(重なっていれば最後に作ったもの)。メモは、ピンを開いて削除。削除は墓標として同期される | 判断 |
| 空のメモ | 作らない・変えない(空にして保存しても、元の内容が残る) | 判断 |
| 蛍光ペンの表示 | 紙の文字が透けるよう、乗算+不透明度45% | 判断 |

### 未対応・制約(第4段階)
- メモの一覧・検索の画面は無い(書き出したMarkdownで見渡す)。
- 蛍光ペンの色・太さの後からの変更は不可(消して引き直す)。
- 書き出しで、注釈が無くなったページの古い画像は、ドライブ上に残る(消さない)。
- Markdown内の画像は相対パス。ドライブの画面上のプレビューでは表示されない場合があり、フォルダごとダウンロードすると表示できる。
